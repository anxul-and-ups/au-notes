### A. AI Agent Intelligence, Multi-Provider & Live Streaming
1. **Live Real-Time Progress & Thinking Visibility:**
   - Chat mein user ko har cheez ka LIVE response dikhna chahiye—agent abhi kya soch raha hai, kaunsa tool call kar raha hai, kitna code/lines generate kar chuka hai, aur kya progress chal rahi hai—taaki user ko screen stuck na lage aur patience bana rahe.
2. **Shallow Outputs, Weak Coding & Broken Graphs:**
   - API key par jo model set hai (Gemini, DeepSeek, etc.), woh apni full coding aur reasoning capability use kyu nahi kar raha? Kitna bhi detailed HTML artifact, slide deck, ya deep explanation maango, agent bahut short mein lapet deta hai aur graphs/SVGs sahi nahi banata.
   - Check karo ki kahan `maxOutputTokens` cap laga hai, system prompt mein brevity restriction hai, ya raw SVG coordinates likhne ki wajah se graphs toot rahe hain (readymade icon packs/charting libraries aur full-depth system prompting ka plan do).
3. **Custom Providers & Multi-Model Reliability:**
   - App mein sirf Gemini 2.5/3.5 Flash aur Flash-Lite hi theek se chal rahe hain; baaki custom providers ke responses bahut late aate hain ya fail ho jaate hain. Timeout, streaming parser, aur provider routing check karo.
4. **Note Editing & Slide Deck Tool Failures:**
   - Bahut baar models note-editing tools ko sahi se invoke nahi kar paate aur slide decks generate karne mein fail ho jaate hain. Tool schema definitions, function calling loop, aur error handling inspect karo.
5. **Context Understanding & Document-to-Slides Pipeline:**
   - Agent abhi bhi conversation context sahi se nahi samajhta. Ise is level par banana hai ki agar user koi PDF, book chapter, ya bada context de, toh agent bina truncation ke uska direct rich HTML ya interactive slide deck bana sake.
6. **Direct OCR / Text Extraction Behavior in Chat:**
   - Jab user chat mein koi image ya file share karke bole ki "iska text de", toh agent extra explanation ya gyaan diye bina sirf clean extracted text output kare.

### B. Chat State Isolation & Performance (Zero Lag / Zero Crash)
7. **Cross-Chat State & Activity Bar Leaking:**
   - Jab ek chat mein agent koi task kar raha hota hai aur user doosri chat par switch karta hai, toh wahi task aur "working/thinking" activity bar doosri chats mein bhi show hone lagti hai. ViewModel/StateFlow ko strictly `chatId` ke hisaab se isolate karo.
8. **HTML / Slides Auto-Render Bug in Active Chat:**
   - Jab chat mein HTML ya slides banke aate hain, toh woh turant load/render nahi hote—pehle kisi doosri chat mein switch karke wapas aana padta hai tab load hote hain. UI recomposition / state emission trigger check karo.
9. **50KB+ Code Crash & App-Wide Lag Fix:**
   - Sirf 50KB ka bada code load karne par app crash/freeze ho jata hai, aur purani chats, bade code notes, HTML Viewer, ya My Documents kholne par device stuck hone lagta hai.
   - Main thread par heavy string/syntax parsing, synchronous DB reads, ya unoptimized WebView rendering kyu ho rahi hai? Async chunked loading, background parsing, aur smooth loading animations ke saath ise completely lag-free aur crash-free banao.

### C. Artifacts, Full-Screen WebView & Save Behavior
10. **Clean Artifact Card & Full-Screen Desktop-Mode Viewer:**
    - Chat mein artifact ke bahar jo extra buttons hain ("Save Artifact", "Open Interactive", etc.), un sabko remove karo.
    - Sirf clean **file ka naam** (ek compact pill/card mein) dikhna chahiye, aur us par tap karte hi woh seedha **Full-Screen Desktop View** mein open ho (abhi screen ki sides khali reh jaati hain—viewport scaling/desktop width fix karo).
11. **Inside-Viewer Save to Notes (WebView-Native Rendering):**
    - Open kiye gaye full-screen artifact ke andar ek clean **Save icon** hona chahiye.
    - Us par tap karne par note aise-waise plain text ki tarah save na ho, balki **Notes ke andar full-screen WebView format** mein save ho taaki kholne par lage ki seedha WebView mein open kiya gaya hai.

    - Split-screen mode ko **Pro-level** banao (smooth resizing/divider, synchronized ya independent scroll, proper state handling).
